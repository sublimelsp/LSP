=> 3.0.0

# Breaking changes

- LSP now utilizes Python's `asyncio` stdlib via the new `sublime_aio` and `websockets` dependencies, which
  Package Control installs automatically. Most of the plugin API stays backward compatible, but
  some APIs were deprecated or changed, and plugin code now runs on a different thread.
  Package authors should read the migration guide:
  https://lsp.sublimetext.io/migrating_to_async_lsp_plugin/
- The `run` method of `LspExecuteCommand` is now a coroutine (`async def run`) and no longer takes an
  edit token. Subclasses that override `run(self, edit, ...)` and call `super().run(edit, ...)`
  must be updated; see the migration guide.

# Features

- `LspTextCommand` and `LspWindowCommand` subclasses can now define `run` as a coroutine
  (`async def run`). Such a method runs on the asyncio thread and, for `LspTextCommand`, does not
  receive an edit token. A regular `def run` keeps working as before.
- `LspTextCommand` and `LspWindowCommand` can be marked "cancellable" on the instance level
  (per view, or per window). A class-level boolean called `cancel_previous_run` can be set
  on the derived class to opt into behavior that cancels the previous run when a new one starts.
- `LspPlugin` hooks, and `@command_handler`, `@request_handler` and `@uri_handler` handlers,
  can now be `async` functions. Handlers that return a `Promise` keep working.
- Add `run_coroutine`, `run_on_asyncio_thread`, `run_on_threadpool`, `run_on_worker_thread`
  and `PortableTimeoutError` to the public API.
- Add `Session.request`, `Session.notify`, `Session.run_command` and `Session.create_task`.

# Enhancements

- Replace the blocking websocket server used by the "remote" `log_server` setting with an
  asyncio-based one (#2957) (Raoul Wols)
